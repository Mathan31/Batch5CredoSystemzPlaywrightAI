# Playwright Framework Generation Guidelines (TypeScript)

## Objective

Generate a production-ready, enterprise-grade Playwright automation framework using TypeScript. The framework must be scalable, maintainable, extensible, and easy for new team members to onboard.

The generated framework should follow modern software engineering practices, SOLID principles, and enterprise automation standards.

---

## Technology Stack

* Playwright (Latest Stable Version)
* TypeScript
* Node.js (LTS)
* Playwright Test Runner
* Allure Reporting
* ESLint
* Prettier
* Faker.js
* dotenv
* GitHub Actions
* Jenkins Ready

---

## Architecture

Implement a layered architecture with strict separation of concerns.

### Layers

1. Test Layer

   * Contains `.spec.ts` files.
   * Should only contain test logic.
   * No locator or UI interaction code.

2. Page Layer

   * Implements Page Object Model (POM).
   * Contains page-level business actions.
   * Must inherit from `BasePage`.

3. Component Layer

   * Reusable UI components.
   * Examples:

     * Header
     * Footer
     * Navigation Menu
     * Side Panel
     * Modal
     * Toast Messages
     * Table Component

4. Service Layer

   * API clients and utilities.
   * REST integrations.
   * Authentication services.
   * API setup/teardown support.

5. Core Layer

   * Base classes.
   * Fixtures.
   * Browser management.
   * Dependency Injection.
   * Common framework utilities.

---

## Design Principles

Strictly follow:

* SOLID Principles
* DRY Principle

* Clean Code Principles
* Single Responsibility Principle

Ensure:

## Dependency Injection

Implement Playwright custom fixtures.

Example:

```typescript

    loginPage,
    dashboardPage,
    homePage
});
```

Requirements:

* Lazy initialization.
* Type-safe fixtures.
* Fixture reuse across tests.
* Support parallel execution.

## Smart Wait Strategy

Requirements:

* Use Playwright Locator API.
* Avoid:

  * waitForTimeout()
  * Hard-coded delays

Preferred:

```typescript
locator.waitFor()
expect(locator).toBeVisible()
page.waitForLoadState()
```

## Error Handling

Implement centralized exception handling.

Create:

```text

```

Responsibilities:

* Capture exceptions.
* Attach screenshots.
* Log failures.
* Preserve stack traces.
* Generate meaningful messages.

Example:


## Acceptance Criteria

The framework MUST:

1. Compile without errors.
2. Execute in Chromium, Firefox, and WebKit.
3. Support parallel execution.
4. Support multiple environments.
5. Support tagging.
6. Support retries.
7. Support Allure and HTML reports.
8. Capture screenshots, videos, and traces on failure.
9. Support API testing.
10. Support network mocking.
11. Support mobile emulation.
12. Support GitHub Actions.
13. Support Jenkins.
14. Follow SOLID principles.
15. Be easy for new automation engineers to extend.
